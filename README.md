# 🍽️ 식사일지 · 온결

식사와 칼로리, 몸무게를 하루 단위로 남기고 달력과 그래프로 확인하는 **개인용 PWA**입니다.
**한국 음식 213종 칼로리 사전**이 들어 있어, 음식 이름을 몇 글자 치면 1회 제공량과 kcal이 자동완성되고 인분(배수)을 눌러 바로 조절할 수 있습니다.
v1.2에서는 **메모 탭**(일일 메모 + 음식 메모 모아보기), **화이트·카키·네이비 3가지 테마**, 음식 행의 **수정·삭제 버튼과 되돌리기**, 읽기 편한 글꼴을 더했습니다.
v1.2.1은 글꼴을 **앱 안에 직접 넣어** Google Fonts 같은 외부 요청을 **0건**으로 만들었고,
v1.2.2는 글꼴을 **Noto Sans KR**(가변 100–900)로 바꾸고 굵기를 한 단계씩 가볍게(본문 400 · 제목/강조 450–500 · 최대 600), 글씨 크기를 한 단계 키웠습니다(본문 16.5px). 획이 가늘고 ㅇ·ㅎ이 둥근 결이라 오래 봐도 편안하고, 오프라인에서도 같은 글꼴로 보입니다.
v1.3은 **통계를 하루 단위로** 바꿨습니다. 월간은 1일부터 말일까지, 연간은 1월 1일부터 12월 31일까지 하루하루의 기록을 월 구분선과 함께 이어 보고, **그래프 크게 보기**와 **점을 눌러 그날 상태 확인 · 그날 기록으로 바로 이동**이 됩니다. 달력·통계 제목을 누르면 **연도·월 빠른 선택 피커**가 열려 작년 5월 같은 날짜로도 한 번에 갑니다. 오늘 탭의 `이번 주` 막대 위에는 날짜별 칼로리 숫자가 표시됩니다.
정적 파일만으로 동작하며, Firebase(Google 로그인 + Cloud Firestore)를 선택적으로 연결하면 기기 간 실시간 동기화가 됩니다.
Firebase 없이도 이 기기의 브라우저 저장소(localStorage)만으로 모든 기능을 쓸 수 있습니다.

## 2. 실행

```bash
cd apps/meal-log
python3 -m http.server 8080
# 브라우저에서 http://localhost:8080
```

> `index.html`을 파일로 바로 열어도 화면은 뜨지만, PWA 설치·서비스 워커·Firebase 로그인은 **http(s) 주소**에서만 동작합니다.

배포는 정적 호스팅이면 어디든 됩니다: GitHub Pages, Netlify, Vercel, Firebase Hosting, Cloudflare Pages.
(`index.html`, `css/`, `js/`, `fonts/`, `icons/`, `manifest.json`, `sw.js` 를 그대로 업로드)

## 3. 파일 구조

```
apps/meal-log/
├── index.html            # 앱 셸 (탭 4개 + 모달 4개)
├── manifest.json         # PWA 매니페스트 (아이콘·테마·바로가기)
├── sw.js                 # 서비스 워커 (앱 셸 오프라인 캐시)
├── firestore.rules       # Firestore 보안 규칙 (본인만 읽고 쓰기)
├── css/styles.css        # 디자인 토큰 + 반응형 + 컴포넌트 (글꼴 @font-face 포함)
├── fonts/                # NotoSansKR-Variable.woff2 (가변 굵기 100–900, 약 1.0MB) + OFL 라이선스
├── js/util.js            # 날짜/숫자 포맷, 이미지 압축, 토스트, 눈금 계산
├── js/foods.js           # 한국 음식 칼로리 사전 213종 (검색·초성·별칭)
├── js/store.js           # 데이터 계층 (localStorage, 백업, 동기화 병합)
├── js/chart.js           # SVG 선 그래프(이중 Y축/따로 보기, 날짜 비율 x축, 수치 라벨·툴팁·점 선택)
├── js/sync.js            # Firebase 초기화·Google 로그인·실시간 구독
├── js/app.js             # 렌더링과 이벤트
├── icons/                # 192·512·maskable·180·32 PNG
└── screenshots/          # 검증 스크린샷
```

의존성 없음(빌드 도구 없이 그대로 동작). 글꼴도 앱 안에 들어 있어 외부 폰트 서버를 쓰지 않습니다. Firebase SDK만 연결 시 CDN에서 동적으로 불러옵니다.

## 4. 화면과 기능

### 오늘 (기록)
- **음식 추가/수정 모달**
  - **칼로리 사전 자동완성**: 음식 이름을 입력하면 `음식명 · 1회 제공량 · kcal` 추천 목록이 바로 뜹니다. 항목을 탭하면 이름과 칼로리가 자동 입력됩니다. `↑/↓` + `Enter` 키보드 조작, `Esc` 닫기도 됩니다.
    - 한국 음식·식재료·음료·간식 **213종**(밥·면·분식·국/찌개·반찬/고기/해산물·빵·과일·유제품/간식·음료·양식)을 1회 제공량 기준으로 수록했습니다.
    - 이름뿐 아니라 별칭·키워드로도 찾습니다. 예) `계란` → 계란후라이·삶은달걀·계란말이·계란찜, `돼지고기` → 삼겹살·목살·제육볶음, `커피` → 아메리카노·카페라떼.
    - **초성 검색** 지원: `ㄱㅊㅉㄱ` → 김치찌개.
    - 사전에 없는 음식은 안내 문구가 뜨고, 기존처럼 자유롭게 직접 입력할 수 있습니다.
  - **인분(배수) 조절**: 사전 음식을 고르면 `0.5 / 1 / 1.5 / 2인분` 칩이 나타나고, 누를 때마다 기준 kcal에 배수가 곱해집니다. 이름도 `김치찌개 1.5인분`, `방울토마토 15개`처럼 함께 바뀌어 기록만 봐도 양을 알 수 있습니다.
    - 칼로리는 언제든 직접 수정할 수 있고, 이름을 직접 고치면 인분을 눌러도 이름은 덮어쓰지 않습니다.
  - 수정 화면에서 사전에 있는 음식(칼로리가 기준값과 같을 때)은 인분 조절을 이어서 쓸 수 있습니다.
- **날짜 이동**: 이전/다음 화살표, `오늘` 버튼. 미래 날짜는 `예정` 배지로 구분.
- **요약 카드**: 총 섭취(kcal), 목표 대비 **게이지(%)**, `섭취 / 목표 / 남은(초과)` 3개 수치.
  - 목표 이내 → 세이지 민트, 초과 → 앰버로 색이 바뀌고 “목표보다 N kcal 더 먹었어요”로 안내.
  - 끼니별 비중 막대 + 범례(아침·점심·저녁·간식).
- **끼니 4섹션**: 아침/점심/저녁/간식. 각 카드에서 음식 추가.
  - **행마다 `✏️ 수정`·`🗑️ 삭제` 버튼**을 항상 보이게 두었습니다(데스크톱은 글자까지, 모바일은 40×40 터치 영역).
  - **삭제는 확인창 없이 즉시 반영**하고, 화면 아래 토스트의 **`되돌리기`**(6초)로 같은 id·칼로리 그대로 되살릴 수 있습니다.
  - `수정`을 누르면 기존 음식 수정 모달이 열려 인분·메모·사진을 그대로 고칠 수 있습니다.
  - 음식명 · 칼로리 · 메모 · **사진**. 사진은 Canvas로 **긴 변 480px / JPEG** 로 줄이고, 필요하면 품질을 0.72 → 0.4까지 낮춰 dataURL 60KB 이하로 맞춥니다. 썸네일을 누르면 원본 보기(라이트박스).
- **몸무게**: 숫자 입력(0.1kg 단위 스텝 버튼), 저장 즉시 이전 기록 대비 증감(↓민트/↑앰버)과 최근 14회 스파크라인.
- **자주 먹는 음식**: 이름·칼로리만 저장. 각 항목의 `아/점/저/간` 칩을 누르면 그 끼니에 **한 번에** 담깁니다. 음식 저장 시 “즐겨찾기에 저장” 체크로도 추가.
- **이번 주**: 일~토 7칸 막대(높이=목표 대비, 민트=이내/앰버=초과). **막대 위에 그날 총 칼로리 숫자**(`1,770` 형식, 기록 없는 날은 `–`)를 함께 보여 주고, 칸을 누르면 그 날짜로 이동.

### 메모
- 상단(모바일은 하단) 내비의 **`메모`** 탭에서 그날의 **일일 메모**를 바로 적고 고칠 수 있습니다.
  - 날짜 이동(◀ ▶ `오늘`)으로 다른 날 메모도 쓰고, 저장 전 변경은 "저장하지 않은 변경"으로 표시됩니다. 날짜를 옮기면 초안은 자동 저장됩니다.
  - `Ctrl/⌘ + Enter` 저장, `메모 지우기`는 즉시 반영 후 **되돌리기** 제공.
- 같은 화면 아래 **메모 모아보기**: 지금까지 남긴 **일일 메모 + 음식별 메모(`item.note`)** 를 최신 날짜순으로 모아 보여 줍니다.
  - `전체 / 일일 메모 / 음식 메모` 필터와 **키워드 검색**(검색어 하이라이트, 음식 이름까지 검색).
  - 일일 메모 항목을 누르면 그 날짜 메모를 편집창에 불러오고, 음식 메모 항목을 누르면 그 음식의 수정 모달로 이동합니다.
- 일일 메모는 `mealLog.v2`의 그날 객체에 **`dayNote`**(선택 필드)로, Firestore에는 `users/{uid}/days/{date}.dayNote`로 함께 저장됩니다. 필드가 없는 예전 기록도 그대로 동작합니다.
- 기록 화면에도 그날 메모가 초록 띠로 보이고 `수정`을 누르면 메모 탭으로 이동합니다. 달력의 날짜 미리보기에도 함께 표시됩니다.

### 테마 (화이트 · 카키 · 네이비)
- 우측 상단 **팔레트 버튼**을 누르면 `화이트 → 카키 → 네이비` 순으로 바로 바뀌고, **⚙️ 설정 → 배경 테마**에서 원하는 테마를 직접 고를 수 있습니다.
  - **화이트**: 기존 기본(밝은 회백색 배경)
  - **카키**: 차분한 올리브빛 배경, 짙은 올리브 글자
  - **네이비**: 밤에 눈이 편한 깊은 네이비 배경, 민트 포인트
- 선택은 `mealLog.v2`의 `settings.theme`에 저장되어 **새로고침·재접속 후에도 유지**되고, 첫 화면이 칠해지기 전(`<head>`)에 적용해 깜빡임이 없습니다.
- Firebase로 로그인했다면 `users/{uid}/profile/settings`의 `theme`에도 저장되어 다른 기기와 맞춰집니다.
- 세 테마 모두 CSS 변수만 바꿔 전환하며, **본문 글자 대비 7:1 이상**, 보조 글자 4.5:1 이상, 카드·달력 점·그래프 선 3:1 이상이 되도록 색을 조정했습니다. 그래프·스파크라인도 테마 색을 읽어 다시 그립니다.

### 달력
- 월간 그리드(6주 고정). 날짜마다 총 섭취와 목표 대비 막대, `오늘` 테두리, 선택 시 네이비 강조.
- **년·월 빠른 선택 피커**: `2026년 11월` 제목을 누르면 연도 목록(기록이 있는 해 + 최근 10년 + 내년, 스크롤)과 12개월 그리드가 열립니다. 연도를 고르고 월을 누르면 바로 그 달로 이동하므로 **작년 5월 같은 날짜도 `<` `>`를 여러 번 누르지 않고 한 번에** 갑니다. 바깥을 누르거나 `Esc`로 닫힙니다.
- 범례: 목표 이내 / 목표 초과 / 기록 없음.
- 하단 월 요약: 기록한 날, 평균 섭취, 목표 이내 비율.
- 날짜를 누르면 아래에 그날의 식사·사진·몸무게가 바로 보이고, **이 날짜 편집**으로 기록 탭에서 수정할 수 있습니다.

### 통계
- **주간 / 월간 / 연간** 전환 + 이전·다음 기간 이동. 기간 제목(`11/22 – 11/28`, `2026년 11월`, `2026년`)을 누르면 달력과 같은 **년·월 빠른 선택 피커**가 열립니다.
- **칼로리(딥 네이비)** 와 **몸무게(세이지 민트)** 선 그래프. **함께 보기**(이중 Y축) / **따로 보기**(두 패널) 토글.
- **하루 단위 그래프**
  - **주간**: 일~토 7일.

## 5. 데이터 구조

localStorage 키: `mealLog.v2`

```jsonc
{
  "version": 2,
  "days": {
    "2026-11-19": {
      "date": "2026-11-19",
      "weight": 72.4,                       // kg, 없으면 null
      "dayNote": "오늘은 산책 20분.",         // 일일 메모 (없으면 "")
      "dayNoteUpdatedAt": 1732000000000,    // 메모 마지막 저장 시각
      "meals": [
        { "id": "…", "type": "breakfast",   // breakfast|lunch|dinner|snack
          "name": "오트밀 40g과 바나나", "kcal": 320, "note": "출근 전",
          "photo": "data:image/jpeg;base64,…", // 480px JPEG, 없으면 null
          "createdAt": 1732000000000, "updatedAt": 1732000000000 }
      ],
      "updatedAt": 1732000000000
    }
  },
  "favorites": [{ "id": "…", "name": "닭가슴살 샐러드", "kcal": 420, "createdAt": 0, "updatedAt": 0 }],
  "settings": { "goal": 2000, "theme": "white" },   // theme: white | khaki | navy
  "meta": { "createdAt": 0, "lastBackupAt": null }
}
```

Firestore 경로:

| 경로 | 내용 |
| --- | --- |
| `users/{uid}/days/{YYYY-MM-DD}` | 하루 기록(식사 배열·몸무게·사진·일일 메모 `dayNote`) |
| `users/{uid}/favorites/{id}` | 자주 먹는 음식 |
| `users/{uid}/profile/settings` | 하루 목표 칼로리 + 테마(`theme`) |

> `dayNote`·`dayNoteUpdatedAt`·`settings.theme`은 **추가된 선택 필드**입니다. 예전 기록에 없어도 기본값(`''`·`0`·`white`)으로 읽고, 앱을 열기만 해서는 저장 데이터를 다시 쓰지 않습니다.
>
> 칼로리 사전(`js/foods.js`)은 **앱에 포함된 정적 자료**입니다. 고른 음식의 이름·칼로리만 기존 `name`/`kcal` 필드에 들어가고, 사전 id나 인분 배수는 기록·localStorage·Firestore에 저장되지 않습니다. 기존 키(`mealLog.v2`)와 문서 구조를 그대로 쓰므로 예전 기록과 섞여도 문제가 없습니다.

`firestore.rules` 는 `users/{uid}/**` 를 **본인만** 읽고 쓸 수 있게 하고 나머지 경로는 전부 차단합니다.
Firebase 웹 구성값(apiKey 등)은 원래 공개되어도 되는 식별자이며, 실제 보호는 이 규칙이 담당합니다.

## 6. Firebase 연결 절차

1. <https://console.firebase.google.com> → **프로젝트 만들기**
2. **Authentication → 로그인 방법 → Google 사용 설정** (지원 이메일 지정)
3. **Firestore Database → 데이터베이스 만들기** (프로덕션 모드로 시작)
4. **Firestore → 규칙** 탭에 이 폴더의 `firestore.rules` 내용을 붙여넣고 **게시**
5. **프로젝트 설정 → 내 앱 → 웹 앱 추가(`</>`)** → 표시되는 `firebaseConfig` 복사
6. 앱 우측 상단 ⚙️ **설정 → Firebase 구성(JSON)** 에 그대로 붙여넣고 **저장하고 연결**
7. **Google 로그인** → 우측 상단 배지가 `동기화됨` 으로 바뀌면 완료
   - 처음 로그인하면 이 기기의 기록이 Firestore로 올라가고, 다른 기기의 기록은 내려받아 병합합니다.
8. 다른 기기에서는 같은 주소로 접속해 **같은 구성값으로 연결 + 같은 Google 계정 로그인**.

> Google 로그인 팝업이 차단되는 환경(일부 모바일 브라우저)에서는 자동으로 리디렉션 방식으로 전환됩니다.
> Authentication → 설정 → **승인된 도메인**에 배포한 도메인이 등록되어 있어야 로그인이 됩니다(localhost는 기본 허용).

### 동기화 규칙(충돌 처리)
- 각 날짜 문서와 즐겨찾기 항목은 `updatedAt`(ms)을 가집니다.
- 같은 날짜를 두 기기에서 고치면 **더 최근에 저장한 쪽이 남습니다**(last-write-wins).
- 수정·삭제는 0.4초 디바운스 후 업로드되고, 다른 기기의 변경은 `onSnapshot`으로 즉시 반영됩니다.

## 7. 프라이버시

- Firebase를 연결하지 않으면 **어떤 데이터도 외부로 나가지 않습니다.** 모든 기록은 이 브라우저의 localStorage에만 있습니다.
- 연결하면 로그인한 본인의 Firestore 영역에만 저장되고, 규칙상 다른 계정은 읽을 수 없습니다.
- 사진은 업로드 전에 기기에서 축소·압축되어 원본이 그대로 올라가지 않습니다.
- 로그아웃해도 이 기기의 로컬 기록은 남습니다. 공용 기기라면 **로컬 기록 모두 지우기**를 사용하세요.
- 브라우저 저장소를 지우면(사이트 데이터 삭제) 로컬 기록도 사라지므로, 주기적으로 **JSON 백업**을 권합니다.
